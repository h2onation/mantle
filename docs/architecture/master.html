The claim

The constant. The rest of the visual shows the engine that serves it.

mywalnut is a conversational tool that helps neurodivergent adults build a Manual of how they actually operate. Jove listens, reflects, and — when something real has accumulated — shows a pattern in the user's own words they couldn't see from inside. The user confirms or refines. The Manual grows.

What's not yet built

The architecture described above includes elements that do not currently fire. Don't infer behavior from the prose alone — these items are decisions or partial wirings, not running code.

The selector · Decision 4's precedence ladder. The structural centerpiece. Not in code; today's substitute is TIER_3_BLOCKS, a flags-keyed multi-block prompt renderer.
The scope-exit gate · The signal source exists in monitor_reads.scope but no code reads it back.
Monitor read-back · Phase 0 is shadow-only by design — the monitor writes to monitor_reads and nothing reads it.
The Contract content · Plumbing in place across three openers; the two sentences naming what Jove does and doesn't do are missing.
The two rupture postures · withdrawal_yield and confrontation_hold. Signal exists in the monitor; postures do not.
Lock 1 · composer fail-closed on thin material · The composer prompts for verbatim user language; no deterministic check enforces it. Soft validators log only.
Per-turn state plumbing for the monitor · Each turn recomputes direction from the 8-message window without the prior turn's read as input. Trajectory isn't anchored.
Recognition decay · Nothing prevents re-surfacing the same pattern across turns or sessions, except a single POST-REJECTION prompt instruction.

Blockers on Lock 1

Three architectural questions to resolve before Lock 1's build prompt can be written. Each is question, recommendation, downstream consequence. From master document section A.

Blocker 1

Where does the selector sit in the pipeline?

question Pre-prompt (output picks which blocks render) or pre-detector (output is a posture name the post-generation pipeline routes on)?
recommended Pre-prompt selector. Shaping the prompt is structural; rewriting the model's output after the fact is stylistic. Decision 4 calls the selector structural.
downstream TIER_3_BLOCKS becomes the selector's output handlers; many flags-keyed blocks collapse into row-specific blocks; applyCheckpointGates becomes the SAVE row's gate.
Blocker 2

What is Surface's ripeness threshold, separate from Save's?

question Today the code has one ripeness check, used both for checkpointApproaching (Save) and any Surface the generator performs. pattern_engaged requires Jove to have already named a pattern — circular if Surface is what produces the naming.
recommended Surface trigger = concrete_examples ≥ 1 and has_charged_language, plus alliance clear from the monitor. pattern_engaged stays on the Save side only. Breaks the circularity by separating "what triggers the naming" from "what gates the writing."
downstream Voice rule R-12 (sequence is evidence → pattern → image → hand back) becomes the Surface row's quality contract — no longer one rule among 21. Future R-12 edits get evaluated against the selector, not against voice alone.
Blocker 3

Does the cross-context requirement hold for non-first checkpoints?

question The standard gate at persona-pipeline.ts:579 requires distinct_contexts ≥ 2 for a non-first checkpoint. Decision 6 says cross-context repetition strengthens but is not required, especially first session. Mismatch.
recommended Drop the hard requirement. Keep distinct_contexts as a strengthening signal — validateHeadline already softens single-example titles with "can" / "sometimes." Aligns with the decision.
downstream Lock 1's verbatim check becomes the primary guardrail against over-claim, matching Decision 6's intent. More single-context Save events, each softened by the headline validator's hedging.

Pre-decision commitments

The constraints inside which the seven decisions get made. They pre-date the decisions and shape the architecture alongside them.

Two-watcher separation

Watcher 1 (alliance monitor) and Watcher 2 (pattern tracker) are separate Anthropic calls; bundling them would starve alliance-watching in favor of pattern-hunting. Non-negotiable.

Monitor gates the tracker

Recognition cannot fire while alliance is in rupture. A "yes" from a sinking user is not a yes. In the selector, alliance rows sit above task rows.

Crisis carve-out

Never-prescribe has exactly one exception: when the user produces crisis signals, Jove DOES prescribe 988 and Crisis Text Line. Tier 1 Rule 6 overrides everything else.

Recognition arc runs once

Re-surfacing the same pattern produces weaker signal (decay). The architecture should not loop the same pattern through Surface across many turns. No code enforces this today.

"Repair" means detect-and-stop

Therapeutic repair gets its force from a real relationship surviving strain. A tool has none. The rupture postures perform the achievable half: detect the rupture, stop the move that produced it. Selector rows will be named withdrawal_yield and confrontation_hold.
